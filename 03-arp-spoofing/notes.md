**Отчёт по главе 2**

ARP-спуфинг и обнаружение ARP-атак
По материалам книги «Этичный хакинг» Дэниела Грэма (2022)

*Цель работы*

Освоить принцип атаки ARP-спуфинг («человек посередине») в изолированной лабораторной сети: провести перехват трафика между двумя узлами, подтвердить перехват, а также разработать собственный скрипт на Python для обнаружения подобных атак.

*Используемые инструменты*

•	arpspoof (пакет dsniff) — отправка поддельных ARP-ответов

•	urlsnarf (пакет dsniff) — перехват HTTP-запросов для подтверждения атаки

•	Python 3 + библиотека Scapy — собственный скрипт обнаружения ARP-атак

•	Параметр ядра net.ipv4.ip_forward — включение пересылки пакетов

*Ход работы*

1. Подготовка — включение пересылки пакетов.
Чтобы атакующая машина могла пропускать через себя трафик между жертвой и маршрутизатором (а не просто обрывать соединение), на атакующей машине была включена пересылка IP-пакетов:
echo 1 > /proc/sys/net/ipv4/ip_forward
2. Запуск ARP-спуфинга в обе стороны.
Атака проводилась одновременно в двух терминалах, чтобы подменить ARP-записи у обеих сторон соединения:
•	В первом терминале атакующая машина представлялась жертве маршрутизатором:
arpspoof -i eth0 -t 192.168.1.101 192.168.1.1
•	Во втором терминале атакующая машина представлялась маршрутизатору жертвой:
arpspoof -i eth0 -t 192.168.1.1 192.168.1.101
В результате весь трафик между жертвой (192.168.1.101) и маршрутизатором (192.168.1.1) начал проходить через атакующую машину.
3. Подтверждение перехвата трафика.
Для проверки того, что атака работает, на атакующей машине был запущен перехватчик HTTP-запросов:sudo urlsnarf

В выводе были успешно зафиксированы HTTP-запросы машины-жертвы (например, обращение к www.google.com), что подтвердило успешность перехвата трафика.


*Разработка скрипта обнаружения ARP-атак*

Для автоматического обнаружения подобных атак на Python (с использованием библиотеки Scapy) был написан скрипт arpDetector.py. Логика скрипта: для каждого перехваченного ARP-пакета сохраняется соответствие MAC-адреса и IP-адреса отправителя; если для уже известного MAC-адреса внезапно появляется другой IP-адрес — выводится предупреждение о возможной ARP-атаке.

Основная функция sniff() библиотеки Scapy использовалась для прослушивания сетевого трафика с фильтром по ARP-пакетам:
sniff(count=0, filter='arp', store=0, prn=processPacket)

Проблема: скрипт не выводил сообщение о ARP-атаке	В функции использовался только return message без print(message) — результат никуда не выводился. Добавлен print() перед return. Дополнительно диагностика через временный print() в начале функции подтвердила, что sniff() корректно ловит пакеты.

Детектор не фиксировал атаку при тестировании	Скрипт запускался уже после остановки процессов arpspoof (атака была неактивна). Решение: запускать детектор первым, затем — активные процессы arpspoof, не прерывая их во время наблюдения.

*Результат*

•	Проведён успешный ARP-спуфинг между жертвой и маршрутизатором в изолированной лабораторной сети

•	Перехват трафика подтверждён с помощью urlsnarf

•	Разработан и отлажен скрипт на Python/Scapy, обнаруживающий признаки ARP-атаки в реальном времени

*Вывод*

Практическая работа продемонстрировала уязвимость протокола ARP к атакам типа «человек посередине» из-за отсутствия встроенной аутентификации ARP-ответов. Также было показано, что подобные атаки можно обнаруживать программным способом — путём отслеживания несоответствия между MAC- и IP-адресами в ARP-трафике. Все действия выполнялись исключительно в изолированной учебной лаборатории.
